设计原则

数据不出设备，除非你主动同步。

01 / 定位

把库存管理从云端收回到本地

码上记面向需要清楚掌握物品归属与数量、同时不愿把数据交给第三方的用户。 产品以「本地存储」为默认状态，以「点对点同步」为可选扩展。

A

隐私默认

数据保存在本机。无需注册账号，不强制联网，不静默上传。

B

扫码驱动

以条码为物品入口，自动校验重复，减少手工录入与串号。

C

设备协作

手机、平板、电脑之间通过系统分享或局域网进行增量同步。

适用场景

  • 个人数码 / 工具箱管理
  • 小团队仓库盘点
  • 工作室物料台账
  • 家庭物资与药品备份

四条主链路，覆盖完整库存生命周期

从识别、建档、留存到迁移，每一步都保持本地可控，并用版本号支撑多设备一致性。

03 / 核心挑战与解决方案

本地多端协作必须先解决三件事

没有中心服务器时，冲突、语义与存储体积会直接暴露在用户面前。方案选择以可预期、可解释为优先。

挑战 01

数据冲突

两台设备离线修改同一条物品的不同字段，再次同步时如何合并，而不是整条覆盖。

解决方案

采用 时间戳机制 + 字段级合并。每个字段携带最后修改时间，合并时以最新时间戳为准；整条记录的 version 用于判断是否需要传输。

挑战 02

条码语义

用户容易误以为扫描条码即可自动获得商品名称、规格与价格。

解决方案

明确产品语义为 自定义物品绑定工具，不是商品百科。扫描只负责生成稳定标识，商品信息由用户手动输入或从既有记录继承。文案与空状态同步说明这一点，避免预期落差。

扫描结果 = 标识符

不自动联网查询商品库 · 不猜测名称与价格

挑战 03

图片存储

现场照片体积大，会导致本地库膨胀、同步包变慢、低配设备卡顿。

解决方案

提供 图片压缩选项，默认将照片控制在 1080p / 500KB 以内。用户可在设置中选择「原图保留」或「优先体积」。

04 / 亮点功能

三个让「本地」真正好用的扩展

增量同步控制成本，局域网面板提升批量效率，加密备份兜住最后一道防线。

H1

增量同步

仅传输 version 发生变化的数据。未改动条目不进入传输队列，降低电量、流量与等待时间。

H2

局域网 Web 面板

手机开启本地服务后，同一 WiFi 下电脑浏览器访问临时面板，适合批量改数量、打标签、导出。

H3

防丢机制

导出 加密备份文件，可在更换设备或系统重置后完整恢复。备份是你自己的保险柜钥匙。

AES · 口令保护 · 可异地保存
